# AI 운영 가이드

작성일: 2026-10-08 · 수정일: 2026-10-20 (문서 검색용 임베딩 모델 추가, 사진 모델은 최후순위) · 대상: 백엔드 (특히 BE B) · 관련 문서: [기술 구조](03_기술_구조.md) 4번

이 문서는 오픈소스 모델 Kanana와 Gemma를 내려받아 우리 장비에서 실행하고, 우리 서버(FastAPI)에서 부르는 방법을 단계별로 적은 것이다.

## 1. 한눈에 보기

```
[Hugging Face / Ollama 저장소]  공개된 모델 파일
        │ ① 한 번만 내려받기
        ▼
[학교 서버 (GPU)]  Ollama가 모델을 그래픽카드에 올려 실행   ← 운영
[4060 Ti PC (Windows)]  같은 방식으로 실행                  ← 개발·예비
        │ ② 질문을 보내고 답을 받음 (OpenAI 호환 형식)
        ▼
[우리 서버 FastAPI]  server/ai/client.py 한 곳에서만 AI를 부름
```

- **학습은 하지 않는다.** 이미 학습이 끝난 모델을 내려받아 **실행**만 한다.
- **모델 파일을 내려받은 뒤에는 인터넷의 AI 회사에 요청하지 않는다.** 질문과 답이 모두 우리 장비 안에서 처리된다. 이것이 "자체 AI"의 뜻이다.
- **비용이 없다.** 모델은 무료로 공개되어 있고, 계산은 우리 그래픽카드가 한다.

## 2. 사용하는 모델

| 이름 | 하는 일 | 받는 곳 | 크기 (압축 후, 대략) |
|---|---|---|---|
| Kanana 1.5 8B Instruct (카카오) | 공지 정리, 판정 조건 변환, 챗봇 답변, 의도 파악, 브리핑 문장 | Hugging Face의 카카오 공식 저장소 | 약 5~6GB |
| 임베딩 모델 (후보: EmbeddingGemma / multilingual-e5) | 문서를 검색용 숫자(벡터)로 바꾸기 | Ollama 목록 또는 Hugging Face | 1GB 안팎 |
| Gemma 3 4B (Google) — 분실물용, 최후순위 | 습득물 사진 설명 | Ollama 공식 모델 목록 | 약 3~4GB |

- 임베딩 모델은 **라이선스와 한국어 검색 성능을 확인한 뒤** 하나로 정하고 이 표와 [기술 구조](03_기술_구조.md)에 기록한다. bge-m3, KURE는 중국 기관(BAAI) 모델 기반이라 제외.
- 모델을 동시에 그래픽카드에 올려 두려면 메모리가 12GB 이상이면 넉넉하다. 그보다 작으면 Ollama가 필요할 때마다 모델을 바꿔 올려서 몇 초가 더 걸린다.

## 3. Ollama 설치

**Ollama**는 오픈소스 모델을 내려받아 그래픽카드에서 돌려 주고, 다른 프로그램이 질문을 보낼 수 있는 주소(API)를 열어 주는 프로그램이다.

| 장비 | 설치 방법 |
|---|---|
| 4060 Ti PC (Windows) | ollama.com에서 Windows 설치 파일을 받아 실행 |
| 학교 서버 (Linux) | `curl -fsSL https://ollama.com/install.sh \| sh` (서버가 켜질 때 자동으로 실행되도록 등록됨) |

설치 확인:

```
ollama --version
nvidia-smi          # 그래픽카드가 보이는지 확인
```

## 4. 모델 내려받기

### Gemma 3 4B (분실물을 할 때만)

```
ollama pull gemma3:4b
```

### 임베딩 모델

Ollama 목록에 있으면 한 줄로 받는다. (예: `ollama pull embeddinggemma` — 정확한 이름은 Ollama 목록에서 확인)

### Kanana 1.5 8B

Ollama 공식 목록에는 없어서 Hugging Face에서 받아 Ollama에 등록한다. 아래 두 방법 중 되는 쪽을 쓴다.

**방법 A: 카카오 공식 파일을 받아 Ollama가 직접 변환**

1. Hugging Face에서 카카오 공식 저장소 이름을 확인한다. (`kakaocorp/kanana-1.5-8b-instruct-...` 형태)
2. 파일을 내려받는다.

   ```
   pip install -U huggingface_hub
   hf download kakaocorp/<저장소 이름> --local-dir ./kanana
   ```

   (예전 버전에서는 `hf` 대신 `huggingface-cli download`)
3. 같은 폴더에 `Modelfile`이라는 파일을 만들고 한 줄을 적는다.

   ```
   FROM ./kanana
   ```

4. 압축하면서 Ollama에 등록한다.

   ```
   ollama create kanana -f Modelfile --quantize q4_K_M
   ```

Kanana는 Llama와 같은 구조로 만들어져 Ollama가 직접 변환할 수 있을 것으로 보지만, 실제로 해 봐야 안다.

**방법 B: 다른 사람이 미리 변환해 둔 파일 사용**

Hugging Face에서 `kanana-1.5-8b-instruct GGUF`로 검색해, 변환된 파일(GGUF)이 있으면 바로 받는다.

```
ollama pull hf.co/<계정>/<저장소>:Q4_K_M
ollama cp hf.co/<계정>/<저장소>:Q4_K_M kanana
```

공식이 아닌 파일이므로 올린 사람과 내려받은 횟수를 확인하고 쓴다.

### 내려받은 뒤 확인

```
ollama list                    # kanana 등이 보이면 성공
ollama run kanana "서경대학교 2학기 장학금 신청 공지를 세 줄로 요약하는 예시를 보여줘"
ollama ps                      # 모델이 GPU에 올라갔는지 확인 (PROCESSOR가 GPU여야 함)
```

**Kanana 답이 이상하게 나올 때** (같은 말 반복, 이상한 기호, 영어로 대답): 대화 형식(chat template)이 제대로 인식되지 않은 것이다. 카카오 저장소의 `tokenizer_config.json`에 있는 대화 형식을 보고 `Modelfile`에 `TEMPLATE`을 직접 적은 뒤 다시 `ollama create`를 한다.

## 5. 우리 서버에서 부르기

Ollama는 OpenAI와 같은 형식의 주소(`http://<주소>:11434/v1`)를 열어 준다. 그래서 `openai` 파이썬 패키지로 부르면 되고, 나중에 장비나 모델을 바꿔도 설정만 고치면 된다.

### 설정 파일 (.env)

```
AI_BASE_URL=http://localhost:11434/v1
CHAT_MODEL=kanana
EMBED_MODEL=<정한 임베딩 모델 이름>
VISION_MODEL=gemma3:4b
```

- 개발할 때: 각자 4060 Ti PC의 Ollama (`localhost`)
- 운영할 때: 학교 서버의 Ollama (우리 서버도 같은 학교 서버에 있으면 그대로 `localhost`)

### AI 호출 코드는 한 파일에만

AI를 부르는 코드는 `server/ai/client.py` 한 곳에만 둔다. 다른 파일은 이 파일의 함수만 쓴다. 아래는 시작용 예시다.

```python
# server/ai/client.py
import base64, os
from openai import OpenAI

_client = OpenAI(base_url=os.environ["AI_BASE_URL"], api_key="ollama")  # Ollama는 키를 검사하지 않음

def ask_json(system: str, user: str) -> str:
    """Kanana에게 묻고 JSON 글자를 받는다. 공지 정리·의도 파악·조건 변환에 사용."""
    res = _client.chat.completions.create(
        model=os.environ["CHAT_MODEL"],
        messages=[{"role": "system", "content": system}, {"role": "user", "content": user}],
        response_format={"type": "json_object"},
        temperature=0.1,
    )
    return res.choices[0].message.content

def embed(texts: list[str]) -> list[list[float]]:
    """문장들을 검색용 숫자(벡터)로 바꾼다. 문서 저장과 챗봇 검색에 사용."""
    res = _client.embeddings.create(model=os.environ["EMBED_MODEL"], input=texts)
    return [d.embedding for d in res.data]

def describe_image(image_bytes: bytes) -> str:
    """Gemma에게 사진을 보여 주고 '종류, 색, 특징'을 받는다. (분실물)"""
    b64 = base64.b64encode(image_bytes).decode()
    res = _client.chat.completions.create(
        model=os.environ["VISION_MODEL"],
        messages=[{"role": "user", "content": [
            {"type": "text", "text": "사진 속 물건의 종류, 색, 특징을 쉼표로 구분한 한국어 단어로만 답해."},
            {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
        ]}],
        temperature=0.1,
    )
    return res.choices[0].message.content
```

- 챗봇 답변처럼 JSON이 아닌 글을 받는 함수도 같은 파일에 같은 방식으로 추가한다.
- JSON이 깨져서 오면 한 번 다시 요청하고, 두 번 실패하면 오류로 처리한다. (8B 모델은 가끔 형식을 어긴다)

### 지시문(프롬프트)은 파일로 관리

지시문은 코드 안에 쓰지 않고 `server/ai/prompts/` 폴더에 일마다 파일 하나로 둔다. 지시문을 고칠 때 코드를 건드리지 않고, 누가 무엇을 바꿨는지 깃허브에서 보인다.

| 파일 | 쓰는 곳 |
|---|---|
| `notice_summary.txt` | 공지 정리 (대상·조건·마감·서류·3줄 요약) + 규정 문장 → 비교할 수 있는 조건 |
| `severity.txt` | 할 일을 놓쳤을 때 피해 크기 1~3 (우선순위) |
| `reason.txt` | 근거 설명 "왜 나에게 해당하는지" |
| `chat_router.txt` | 챗봇의 의도 파악 (내 정보 / 문서) |
| `chat_answer.txt` | 챗봇의 문서 근거 답변 |
| `my_info_answer.txt` | 챗봇의 내 상황 답변 (계산해 둔 결과로) |
| `briefing.txt` | 홈 브리핑 문장, 추천 질문 (메뉴 칸 문구는 숫자라 코드가 씀) |
| `image_describe.txt` | 습득물 사진 설명 (분실물, 아직 없음) |

> MVP 뼈대(10/23)는 `AI_FAKE=1`(가짜 AI, `server/ai/fake.py`)로 동작합니다. 위 지시문은 진짜 모델용으로 미리 써 두었습니다.

## 6. 학교 서버 운영 설정

| 할 일 | 방법 | 이유 |
|---|---|---|
| 외부에서 Ollama에 접속 못 하게 하기 | Ollama 기본값(이 서버 안에서만 접속)을 그대로 둔다. 우리 서버가 다른 장비에 있으면 방화벽으로 그 장비 주소만 허용한다 | 열어 두면 누구나 우리 GPU를 쓸 수 있음 |
| 모델을 항상 올려 두기 | Linux: `sudo systemctl edit ollama`에 `Environment="OLLAMA_KEEP_ALIVE=-1"` 추가 후 재시작. Windows(4060 Ti PC): `setx OLLAMA_KEEP_ALIVE -1` 후 Ollama 종료·재실행. API 서버는 켜질 때 모델을 미리 올림(`ai/client.py` `warm_up`) | 기본값은 일정 시간 안 쓰면 모델을 내려서, 다음 질문 때 몇 초 늦어짐 |
| 서버가 다시 켜져도 자동 실행 | 설치 스크립트가 자동 등록함. `systemctl status ollama`로 확인 | 시연 중 재부팅 대비 |

## 7. 문제가 생길 때

| 증상 | 확인할 것 |
|---|---|
| 답이 아주 느림 (수십 초) | `ollama ps`에서 PROCESSOR가 CPU로 나오면 GPU를 못 쓰는 것. 그래픽카드 드라이버와 `nvidia-smi` 확인 |
| 모델을 바꿔 쓸 때만 몇 초 늦음 | 그래픽카드 메모리가 부족해 모델을 바꿔 올리는 중. 그대로 두거나 모델 하나를 다른 장비로 옮김 |
| Kanana 답이 이상함 | 4번의 "답이 이상하게 나올 때" 참고 |
| JSON이 깨져서 옴 | 지시문에 형식 예시를 넣고, 서버에서 한 번 다시 요청. 두 번 실패하면 오류로 처리 |
| 우리 서버가 AI를 못 찾음 | `.env`의 `AI_BASE_URL` 주소와 Ollama 실행 여부(`ollama list`) 확인 |

## 8. 발표·보고서용 설명

> 우리 서비스는 외부 AI 회사의 유료 API를 쓰지 않습니다. 카카오가 공개한 한국어 특화 모델 Kanana를 학교 서버의 GPU에서 직접 실행합니다. 학생의 학적·성적 같은 정보와 질문 내용이 학교 밖 AI 회사로 나가지 않고, 사용량이 늘어도 AI 사용료가 들지 않습니다. 모델과 장비 주소는 설정 파일로 분리되어 있어, 더 좋은 공개 모델이 나오면 코드 수정 없이 교체할 수 있습니다.

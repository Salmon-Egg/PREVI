## 0. 확정 사항 (10/20)

v3.0과 새 기획안이 달랐던 부분을 아래처럼 정했다. **v3.0 8번(표)·9번(API·형식)·12번(팀 규칙 4)은 이 내용으로 갱신해야 한다** (팀 규칙 1: 조장 확인).

| # | 항목 | 결정 | 작업에 미치는 영향 |
|---|---|---|---|
| 1 | 성적 | **학생이 직접 입력** (학기별 과목·학점·성적) | grades 표·API 신설. v3.0 팀 규칙 4("평점은 받지 않음") 수정, 동의 문구에 성적 추가 |
| 2 | AI | **자체 AI 유지** (Ollama + Kanana/Gemma) + 문서 검색용 임베딩 모델 추가 | 학교 서버 확인 마감 10/23. 막히면 4060 Ti PC + Tunnel, 최후에는 설정 주소만 바꿔 외부 API |
| 3 | 화면 구조 | **새 기획안대로** 홈 허브 + 메뉴 4칸 + 상단 알림/프로필 | v3.0의 하단 탭 5개 폐기. 비서 버블은 없음 |
| 4 | 알림 | 본인에게 알려야 하는 알림은 **서버 푸시** | Expo 푸시 + EAS 개발 빌드 필수. 앱 안에서는 T-4 알림 센터 |
| 5 | 공지 수집 | **자동 수집** (정해진 시각에 수집 → AI 정리) | v3.0 공지 수집기(httpx + BeautifulSoup + cron) 유지. 수집은 코드, 정리는 AI |
| 6 | 관리자 | **추후 추가** | 이번 범위에서 AD-1~AD-7 전부 제외. 학사요람·학사일정은 BE가 스크립트로 넣음 |
| 7 | 분실물 | **최후순위** | 다른 필수·권장이 다 끝난 뒤에만 착수. 메뉴는 3칸안(분실물 칸 빼기)을 기본으로 둠 |

### 자체 AI 구성

| 용도 | 모델 | 비고 |
|---|---|---|
| 공지 정리, 판정용 조건 변환, 챗봇, 의도 파악, 브리핑 문장 | Kanana 1.5 8B Instruct (카카오) | v3.0 그대로 |
| 문서 검색용 임베딩 | **EmbeddingGemma**(Google) 또는 **multilingual-e5**(Microsoft) — 후보 | 신규. bge-m3·KURE는 중국 모델(BAAI) 기반이라 제외. 라이선스 확인 후 v3.0 6.3에 기록 |
| 사진 설명 (분실물, 최후순위) | Gemma 3 4B (Google) | 분실물을 하지 않으면 안 올려도 됨 |

**위험과 대응**
- 학교 서버 미확인(GPU 메모리, 외부 접속, 11/12까지 가동, 설치·cron 허가) → **10/23까지 확인**, 안 되면 4060 Ti PC를 운영 장비로 전환
- 학생 수만큼 AI를 부르는 일(⑤ 브리핑, ⑥ 근거, ⑦ 추천 질문) → 시연은 페르소나 4명이라 문제없음. 실패·지연 시 문장 틀(템플릿)로 대체하도록 만든다
- 8B 모델의 JSON 출력 깨짐 → `client.py`에서 형식 검증 + 1회 재시도

우선순위 표기: **[필수]** · [권장] · (선택) · ~~최후~~ = 분실물

# 기술 구조

앱이 어떻게 생겼고 무엇으로 만드는지 정리한 문서입니다. (2026-10-20 팀 결정 반영)

---

## 1. 한 장 그림

```
[모바일 앱 (Expo)]
   │  로그인 ─────────────────▶ [Supabase 로그인]
   │  휴대폰 알림 ◀──────────── [Expo 푸시 서비스] ◀───────┐
   │  그 외 모든 요청                                       │ 알림 보내기
   ▼                                                       │
┌──────────────────────── 학교 서버 ────────────────────────┐ │
│ [우리 서버 FastAPI] ───────────────────────────────────────┼─┘
│    │  정해진 시각 작업 (cron)                              │
│    │    - 9·13·18시: 공지 수집 → AI 정리 → 대상 학생 판정 → 알림
│    │    - 매일 아침: 마감·졸업 요건·장학 판정 → 오늘 챙길 일 → 알림
│    │                                                      │
│    └──▶ [자체 AI: Ollama + GPU]  ※ 이 서버 안에서만 접속됨   │
└───────────────────────────────────────────────────────────┘
         │
         ├──▶ [Supabase 데이터베이스 · 사진 저장소]
         └──▶ [학교 공개 게시판]
```

**한 줄 요약**: 앱은 로그인만 Supabase와 직접 하고, 나머지는 전부 우리 서버를 거칩니다. AI와 알림도 우리 서버만 다룹니다.

## 2. 확정된 결정 (10/20)

| 항목 | 결정 |
|---|---|
| 화면 구조 | 홈 허브(캐릭터·오늘 챙길 일·메뉴 칸) + 상단 알림·프로필 아이콘. 하단 탭은 쓰지 않음 |
| 성적 | 학생이 직접 입력 |
| AI | 자체 AI (학교 서버 GPU에서 오픈소스 모델 실행). 외부 AI 회사 서비스는 쓰지 않음 |
| 알림 | 본인에게 알려야 하는 것은 서버가 휴대폰으로 푸시 |
| 공지 | 학교 공개 게시판에서 자동 수집, AI가 정리 |
| 관리자 기능 | 추후 추가 (이번에는 만들지 않음) |
| 분실물 | 최후순위 (다른 것이 다 끝나면) |

## 3. 사용하는 도구

| 영역 | 도구 | 쉽게 말하면 |
|---|---|---|
| 앱 | Expo (React Native) + Expo Router | 코드 하나로 안드로이드·아이폰 앱을 만드는 도구, 화면 이동 |
| 앱 빌드 | EAS Build (개발 빌드) | 푸시 알림을 받으려면 Expo Go 대신 우리 앱을 빌드해서 설치해야 함 |
| 휴대폰 알림 | Expo 푸시 + expo-notifications | 서버가 휴대폰으로 알림을 보내는 통로 (무료) |
| 서버 | Python FastAPI | 앱의 요청을 받아 처리. API 문서가 자동으로 생김 (`/docs`) |
| 로그인·DB·사진 | Supabase | 회원가입·이메일 인증, 데이터 저장, 사진 보관 |
| 문서 검색 | Supabase pgvector | 학사요람 같은 문서를 문단으로 나눠 저장하고 비슷한 문단을 찾음 |
| 공지 수집 | httpx + BeautifulSoup | 웹 페이지를 읽어 글을 뽑아내는 도구 |
| 정해진 시각 작업 | cron | 서버가 정해진 시각에 프로그램을 실행 |
| AI 실행 | Ollama | 오픈소스 AI 모델을 그래픽카드에서 돌려 주는 프로그램 |
| AI 호출 | openai 파이썬 패키지 | Ollama가 OpenAI와 같은 형식을 써서 그대로 사용 |
| 외부 연결 | Cloudflare Tunnel (필요할 때만) | 학교 밖에서 학교 서버에 접속할 수 있게 함 |

## 4. 자체 AI

| 용도 | 모델 | 비고 |
|---|---|---|
| 공지 정리, 판정 조건 변환, 챗봇, 질문 의도 파악, 브리핑 문장 | **Kanana 1.5 8B Instruct** (카카오) | 한국어 중심, Apache 2.0 |
| 문서 검색용 임베딩 | **EmbeddingGemma 300M** (Google) | 확정 (10/25). 768차원, Gemma 이용약관 |
| 사진 설명 (분실물, 최후순위) | Gemma 3 4B (Google) | 분실물을 하지 않으면 설치 안 함 |

### 라이선스 (10/25 확인)

| 모델 | 받은 곳 (Ollama 이름) | 라이선스 | 우리가 지킬 것 |
|---|---|---|---|
| Kanana 1.5 8B Instruct | `hf.co/mradermacher/kanana-1.5-8b-instruct-2505-GGUF:Q4_K_M` (카카오 원본 `kakaocorp/kanana-1.5-8b-instruct-2505`를 4bit로 줄인 파일) | Apache 2.0 | 상업 이용 가능. 발표 자료·README에 모델 이름과 라이선스 표기 |
| EmbeddingGemma 300M | `embeddinggemma:300m` | Gemma 이용약관 (Gemma Terms of Use) | 상업 이용 가능. Gemma 금지 용도 정책을 지키기. 모델 파일을 남에게 나눠 주지 않으므로 약관 사본 첨부 의무는 해당 없음 |

- multilingual-e5(MIT)는 후보였으나 EmbeddingGemma가 Ollama에서 바로 받아지고 크기(768)가 DB 표와 맞아 선택하지 않음
- 두 모델 모두 중국 모델·파생 모델이 아님 (모델 고르는 조건 충족)

- **학습은 하지 않습니다.** 공개된 모델을 내려받아 실행만 합니다.
- **모델 고르는 조건**: 무료, 한국어를 잘함, 그래픽카드 한 대에서 돌아감, **중국 모델과 그 파생 모델 제외**
- 설치·호출 방법은 [AI 운영 가이드](06_AI_운영_가이드.md)

### 숫자는 AI가 아니라 코드가 계산

| AI가 하는 일 | 코드가 하는 일 |
|---|---|
| 공지 글에서 대상·조건·마감·서류 뽑기, 3줄 요약 | 학생 정보와 조건 대조 → 신청 가능/조건 미충족/확인 필요 |
| 규정 문장을 비교할 수 있는 조건으로 바꾸기 | 졸업 학점 합산, 남은 학점 계산 |
| "놓쳤을 때 얼마나 큰일인지" 판단 | D-day 계산, 시간 중복 확인 |
| 브리핑 문장, 근거 설명, 추천 질문 쓰기 | 정렬, 중복 알림 막기 |

학생 수만큼 AI를 부르는 일(브리핑·근거·추천 질문)은 AI가 실패하거나 느리면 **문장 틀(템플릿)로 대신** 보여 줍니다.

### 챗봇이 답하는 순서
1. 질문을 받으면 AI가 "내 정보 질문인지, 문서 질문인지" 고릅니다. (정해진 JSON 모양으로만 답하게 함)
2. 내 정보 질문 → 아침에 계산해 둔 결과로 답합니다.
3. 문서 질문 → 문서에서 비슷한 문단을 찾아 그것을 근거로 답하고, 출처를 붙입니다.
4. **근거가 없으면 "모른다"고 답하고** 그 질문을 기록해 둡니다. (나중에 관리자 기능에서 사용)

## 5. 알림

- **모든 알림은 서버의 발송 함수 하나로만** 보냅니다.
- 보낼 때마다 `notifications` 표에 기록하고, 같은 사람·같은 대상·같은 종류의 기록이 있으면 다시 보내지 않습니다.
- 학생이 꺼 둔 종류의 알림은 보내지 않습니다.
- 공지 수집은 낮 시간(9·13·18시)에만 해서 밤에 알림이 울리지 않게 합니다.

| 종류(type) | 보내는 때 | 예시 |
|---|---|---|
| `notice` | 수집한 공지가 나에게 해당될 때 | "2학기 교내 장학금 신청 공지가 올라왔어요. 마감 10/30" |
| `deadline` | 할 일 마감 전날·당일 (학생이 정한 시간) | "장학금 신청 마감이 내일이에요" |
| `calendar` | 학사일정 3일 전·당일 | "수강 정정이 3일 뒤 시작돼요" |
| `chat` | 질문하고 앱을 떠났는데 답이 나왔을 때 | "졸업 요건 질문에 답변이 도착했어요" |

## 6. 장비

| 장비 | 용도 |
|---|---|
| 학교 서버 (GPU) | 운영. 우리 서버와 AI를 함께 올림. 시연도 여기서 |
| 4060 Ti PC ① | BE B 개발·실험용 |
| 4060 Ti PC ② | BE A 개발용. 학교 서버가 안 되면 예비 운영 장비 |

장비가 바뀌어도 `.env`의 주소만 바꾸면 되고 코드는 그대로입니다.

## 7. 이번에 만들지 않는 것

| 뺀 것 | 대신 |
|---|---|
| 관리자 화면 전체 | 학사요람·학사일정·졸업 기준은 BE가 스크립트로 넣음. 미응답 질문은 기록만 |
| 모델 추가 학습 | 지시문 + 문서 검색 |
| 학교 포털·종합정보시스템 연동 | 학생이 직접 입력 |
| 다른 앱 위에 뜨는 버블 | 일반 휴대폰 알림 |
| 전 학과 졸업 요건 | 소프트웨어학과·전자컴퓨터공학과만 |
| 여러 명 동시 사용 대응 | GPU 한 대로 순서대로 처리 |

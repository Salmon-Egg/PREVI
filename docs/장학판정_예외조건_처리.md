# 장학 판정 예외 조건 처리

2026-10-29 · BE A 구현 · AI JSON 및 DB 필드 변경 없음

## 처리 범위

기존 `conditions.min_credits`는 직전 학기 이수 학점 하한 숫자 하나만 표현한다. 공지에 “15학점, 단 8학기는 12학점”이 있으면 일반 기준만 비교해서 신청 가능 학생을 탈락시킬 수 있다.

- AI의 `conditions.unknown` 또는 공지 원문에서 학기별 학점 예외가 확인되면 이수 학점 조건은 `check`(확인 필요)로 둔다. 12학점이나 15학점이라는 이유만으로 통과·탈락시키지 않는다.
- 앱의 4학년 2학기를 실제 등록 8학기나 장학 심사 대상 학기로 간주하지 않는다. 편입·초과학기·휴복학·심사 시점 때문에 다를 수 있다.
- 평점·대상 학과 등 별도의 확정된 미충족 조건은 계속 `ineligible`로 판정한다.
- AI가 누락했더라도 원문에 토익·TOEIC 점수 하한이나 학사경고 제외 조건이 있으면 직접 확인이 필요한 조건으로 남긴다. 해당 정보는 현재 프로필·성적으로 확정할 수 없다.
- 토익 시험 일정처럼 점수 자격 조건이 없는 문장은 이 처리로 자격 제한을 만들지 않는다.
- 일반적인 직전 학기 학점 하한 비교는 그대로 유지한다. 입력된 조건 객체를 수정하지 않는다.

## 한계와 BE B 협의 항목

이번 변경은 조건을 임의 해석해 예외 대상자를 확정하는 구현이 아니다. 현재 구조에서 잘못된 통과·탈락을 막는 보수적 처리다. 일반 학점 미달이어도 예외에 해당할 가능성이 있으면 확인 필요가 된다.

예외를 자동 계산하려면 AI가 일반 기준·예외 기준·대상 학기·그 학기가 현재/직전/등록 학기 중 무엇인지 구분해서 반환하고, 학생의 실제 적용 학기를 확인할 정보가 있어야 한다. 이 함수 계약·학생 데이터 확장은 BE B 및 FE와 별도 합의한다.

공지 원문·기존 unknown에서 확인되는 범위만 처리하므로 첨부 파일에만 있는 조건까지 복구할 수는 없다. 이미 저장된 eligibility는 다음 학생 재계산 또는 아침 점검에서 반영된다. 이 PR 자체가 운영 DB를 일괄 변경하거나 푸시를 발송하지 않는다.

## 검증

학점 12·15인 학생의 학기 예외, AI 누락 시 원문 확인, 일반 학점 기준 유지, 평점 미달 우선, 토익·학사경고 정보 미확인, 토익 일정 오인 방지, 학생별 파이프라인 연결을 테스트한다.

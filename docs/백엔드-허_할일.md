# 백엔드-허 — BE B(AI 담당) 할 일과 두 컴퓨터 작업 가이드

이 브랜치(`백엔드-허`)는 컴퓨터 2대에서 번갈아 작업하는 내 전용 브랜치입니다.
다 끝나면 GitHub에서 `백엔드-허` → `mvp`로 PR을 올려 팀에 합칩니다.

---

## 1. 한눈에 보는 구조 (식당 비유)

| 식당 | 우리 서비스 |
|---|---|
| 주문 태블릿 | **앱** (학생 폰) |
| 주방 | **서버** = 우리 GPU 컴퓨터 (FastAPI) |
| 요리사 | **AI 모델** (Ollama + Kanana 1.5 8B) |
| 요리책 | **학사요람·공지** (Supabase DB, doc_chunks) |
| 알아서 챙기는 매니저 | **에이전트** (`server/agent.py`, `server/jobs/`, `server/ai/tasks.py`) |
| 배달 통로 | **Cloudflare Tunnel** (무료, 폰 → GPU 컴퓨터) |

- 모델은 **학습하지 않고** 지시문(`server/ai/prompts/`) + 문서 검색으로 우리 서비스에 맞춥니다.
- GPU가 없는 컴퓨터에서는 `.env`의 `AI_FAKE=1`(가짜 AI)로 개발을 계속할 수 있습니다.

## 2. 다른 컴퓨터에 처음 받아오기 (한 번만)

### 2-1. 설치할 프로그램
- Git: https://git-scm.com
- GitHub Desktop (팀 기본): https://desktop.github.com — 로그인까지
- Python 3.11 이상: https://www.python.org (설치할 때 "Add to PATH" 체크)
- Node.js LTS: https://nodejs.org (앱도 돌려 볼 때만)

### 2-2. 레포 받기 (클론)
**GitHub Desktop**
1. File → Clone repository → `Salmon-Egg/front-back-kick` 선택 → Clone
2. 위쪽 **Current branch** 클릭 → `origin/백엔드-허` 선택 (내 컴퓨터에 `백엔드-허`가 생김)

**명령어로 할 때**
```bash
git clone https://github.com/Salmon-Egg/front-back-kick.git
cd front-back-kick
git switch 백엔드-허
```

### 2-3. 깃에 안 올라가는 파일 옮기기 (중요)
아래 파일은 비밀번호·키가 들어 있어서 **깃허브에 올리지 않습니다.** 원래 컴퓨터에서 직접 복사해 오세요.
(USB, 카톡 나에게 보내기 등. 공개된 곳에는 올리지 않기)

| 파일 | 놓을 위치 | 없으면 |
|---|---|---|
| `.env` | 레포 맨 위 | `.env.example`을 복사해서 이름을 `.env`로 바꾸고 팀 단톡방 값으로 채우기 |
| `app/.env` | `app/` 폴더 | `app/.env.example`을 복사해서 채우기 |

### 2-4. 서버 준비
```bash
cd server
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```
실행 확인:
```bash
uvicorn main:app --reload
```
브라우저에서 http://localhost:8000/health 가 열리면 성공.

### 2-5. (앱도 돌려 볼 때만)
```bash
cd app

npx expo start
```

## 3. 매번 지키는 규칙: "앉으면 pull, 일어나기 전에 push"

| 언제 | GitHub Desktop | 명령어 |
|---|---|---|
| **작업 시작 전** | Fetch origin → Pull origin | `git pull` |
| **자리 뜨기 전** | 왼쪽 아래에 메모 쓰고 Commit → Push origin | `git add .` → `git commit -m "한 일"` → `git push` |
| 가끔 팀 변경 받기 | Branch → Update from `mvp` | `git pull origin mvp` |

- 푸시를 깜빡하고 다른 컴퓨터에서 작업하면 충돌이 납니다. 자리 뜨기 전에 꼭 Push.
- `.env`를 바꿨다면 다른 컴퓨터에도 직접 옮겨야 합니다. (깃으로 안 넘어감)
- 모델 파일(`*.gguf`)은 깃에 안 올라갑니다. Ollama가 컴퓨터마다 따로 받습니다.

## 3-1. 팀 결정 (10/27)
- DB·서버 코드는 **BE A 브랜치(`be/server-auth`) 기준**으로 합친다. DB·서버는 BE A 담당.
- `agent.py`·`jobs/` 연결 = BE A. AI(`server/ai/`)·문서 검색·챗봇 답변 = BE B.
- 그래서 내 AI 코드는 BE A 서버의 표(`notices.target`·`conditions` 등)에 맞춰 옮겨야 함.
- 처리 못 한 장학 조건(토익·학사경고 등)은 AI가 `conditions.unknown`(문장 목록)에 넣고, 판정 코드(`logic/eligibility.py`)는 이게 있으면 "확인 필요".

## 3-2. `통합본` 브랜치 (10/27~) — 이제 여기서 작업
`mvp` + `fe/mvp2` + `백엔드-허` + `be/server-auth`를 합친 최종 브랜치. 서버·DB는 BE A 구조(Supabase REST, `server.` 경로).
- 예전 서버 전용 파일(`db.py`, `agent.py`, `jobs/daily_check.py`, `scripts/init_db.py`·`local_db.py`, `001_init.sql`, `seed.sql`)은 지움 → **아래 5번의 로컬 DB 방법은 더 이상 안 씀**
- BE B가 옮긴 것: `server/ai/`(설정은 `ai/client.py`가 `.env`에서 직접 읽음), `routes/chat.py`(`/chat`, `/conversations`), `supabase/migrations/009_chat_documents.sql`(문서·대화 표 + 벡터 검색 함수 `match_doc_chunks`), `scripts/load_yoram.py`(Supabase에 넣음)
- 실행 (저장소 맨 위 폴더에서):
  1. `.env`에 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` (BE A에게 받기), `AI_FAKE=1`
  2. Supabase SQL Editor에서 `supabase/migrations/001~009` 순서대로 실행 (BE A가 이미 했으면 009만)
  3. `python -m server.scripts.load_yoram` → "학사요람 문단: 249개, 장학금 규정 문단: 19개"
  4. `python -m uvicorn server.main:app --reload` → http://localhost:8000/health
  5. 테스트: `python -m pytest server/tests -q` (159개, 10/27 통과)
- 10/27 밤 `fe/mvp3`(최종 FE) 합침. 서버에 붙인 것:
  - `/chat`이 `context.kind = "status"`(A-3 휴·복학 화면) 받음
  - `/me`가 `assistant_scope`(비서가 볼 정보), `notify.quiet`(방해 금지 시간) 받음 → **Supabase에 `010_profile_assistant_quiet.sql` 실행 필요**
  - 시연 학생 4명: 대시보드에서 `학번@skuniv.ac.kr` 계정 4개 만들기(Auto Confirm) → `python -m server.scripts.seed_personas` (학적 4명 + 홍길동 성적 43과목)
  - 앱 `app/.env`: `EXPO_PUBLIC_USE_MOCK=0`, `EXPO_PUBLIC_DEV_LOGIN=0`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`(= publishable 키), `EXPO_PUBLIC_EMAIL_DOMAIN=skuniv.ac.kr`
- 남은 것: 공지 AI 정리(pending → ready)와 학생별 판정(`eligibility`)을 `jobs/`에 연결 = BE A. 내 함수는 `ai.tasks.summarize_notice`, `logic.eligibility.judge`.

## 5. 다른 PC(그래픽카드 없음)에서 바로 시작하기

1. `git pull` (브랜치 `백엔드-허`)
2. `.env`는 **`AI_FAKE=1` 그대로** 둔다. `EMBED_MODEL`은 비워 둔다. (가짜 AI·글자 검색으로 동작)
3. DB가 꺼져 있으면 (컴퓨터를 껐다 켜면 꺼짐):
   ```bash
   C:\pgenv\Scripts\python server\scripts\local_db.py
   ```
   출력된 주소를 `.env`의 `DATABASE_URL`에 넣기. (포트가 바뀔 수 있음. `C:\pgenv`가 없으면 `local_db.py` 맨 위 설명대로 만들고 `python -m scripts.init_db`)
   - 다른 PC(DESKTOP-VOMEBL8)는 `C:\pgenv` 없이 `server\.venv`에 pgserver가 들어 있음: `server\.venv\Scripts\python server\scripts\local_db.py`
4. 서버 켜기: `cd server` → `.venv\Scripts\activate` → `uvicorn main:app --reload` → http://localhost:8000/health
5. 시험할 때 로그인: 요청 머리에 `Authorization: Bearer dev-00000000-0000-0000-0000-000000000001` (`.env`에 `DEV_AUTH=1`일 때)

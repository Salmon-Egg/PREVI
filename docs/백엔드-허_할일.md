## 3. 매번 지키는 규칙: "앉으면 pull, 일어나기 전에 push"

| 언제 | GitHub Desktop | 명령어 |
|---|---|---|
| **작업 시작 전** | Fetch origin → Pull origin | `git pull` |
| **자리 뜨기 전** | 왼쪽 아래에 메모 쓰고 Commit → Push origin | `git add .` → `git commit -m "한 일"` → `git push` |
| 가끔 팀 변경 받기 | Branch → Update from `mvp` | `git pull origin mvp` |

- 푸시를 깜빡하고 다른 컴퓨터에서 작업하면 충돌이 납니다. 자리 뜨기 전에 꼭 Push.
- `.env`를 바꿨다면 다른 컴퓨터에도 직접 옮겨야 합니다. (깃으로 안 넘어감)
- 모델 파일(`*.gguf`)은 깃에 안 올라갑니다. Ollama가 컴퓨터마다 따로 받습니다.

## 3-2. `통합본` 브랜치 (10/27~) — 이제 여기서 작업
`mvp` + `fe/mvp2` + `백엔드-허` + `be/server-auth`를 합친 최종 브랜치. 서버·DB는 BE A 구조(Supabase REST, `server.` 경로).
- 예전 서버 전용 파일(`db.py`, `agent.py`, `jobs/daily_check.py`, `scripts/init_db.py`·`local_db.py`, `001_init.sql`, `seed.sql`)은 지움 → **아래 5번의 로컬 DB 방법은 더 이상 안 씀**
- BE B가 옮긴 것: `server/ai/`(설정은 `ai/client.py`가 `.env`에서 직접 읽음), `routes/chat.py`(`/chat`, `/conversations`), `supabase/migrations/009_chat_documents.sql`(문서·대화 표 + 벡터 검색 함수 `match_doc_chunks`), `scripts/load_yoram.py`(Supabase에 넣음)
- 실행 (저장소 맨 위 폴더에서):
  1. `.env`에 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` (BE A에게 받기), `AI_FAKE=1`
  2. Supabase SQL Editor에서 `supabase/migrations/001~009` 순서대로 실행 (BE A가 이미 했으면 009만)
  3. `python -m server.scripts.load_yoram` → "학사요람 문단: 249개, 장학금 규정 문단: 19개"
  4. `python -m uvicorn server.main:app --reload` → http://localhost:8000/health
  5. 테스트: `python -m pytest server/tests -q` (159개, 10/27 통과)

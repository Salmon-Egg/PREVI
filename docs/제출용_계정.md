# 제출용 계정

관리자 웹 아이디는 `test_admin`, 학생 앱 아이디는 `test_student`다. 비밀번호는 별도로 전달하며 저장소와 서버 환경 파일에 기록하지 않는다.

Supabase Auth 관리 API로 이메일 확인을 완료한 계정과 빈 학생 프로필을 생성했다. 내부 인증 식별자는 각각 `test_admin@example.com`, `test_student@example.com`이며 이메일을 발송하지 않는다. 일반 회원가입의 학교 이메일 제한과 학생 데이터의 RLS는 유지한다.

학교 서버에서 최신 통합본을 받은 뒤 실행한다.

```bash
cd ~/front-back-kick &&
.venv/bin/python -m server.scripts.configure_submission_accounts --apply &&
systemctl --user restart previ-api.service &&
systemctl --user restart previ-share.service
```

설정 도구는 인증 서버가 관리하는 `app_metadata`로 생성 계정을 확인하고, 기존 관리자 목록에 제출용 관리자 이메일을 추가한다. 두 계정의 UUID만 `DEMO_USER_IDS`에 추가하여 학교 이메일 검사를 예외 처리한다. 학생 계정은 관리자 목록에 넣지 않는다. 기존 `.env`는 권한 600으로 백업한다. 관리자 웹은 자동 배포 완료 후, 학생 웹은 재빌드 완료 후 새 아이디로 로그인한다. 학생의 학과·학년·동의 등은 첫 로그인에서 직접 설정한다.

제출용 관리자는 실데이터를 조회·수정·영구 삭제할 수 있다. 심사 종료 후 두 계정을 비활성화하고 허용 목록에서 제거해야 한다. 이미 로그인한 세션도 만료시켜야 한다.

검증: 서버 테스트 322개와 학생 앱 타입 검사 통과. 실제 Supabase 계정으로 새 서버 코드에서 두 계정의 `/me` 200, 관리자 계정의 `/admin/summary` 200, 학생 계정의 관리자 접근 403 확인. 관리자 JSX 문법 검사 통과. 로컬 관리자 웹 전체 빌드는 Windows 네이티브 도구 종료 오류로 완료하지 못했고, 학생 앱 lint는 기존 ESLint 설정 부재로 미완료다. 학교 서버 적용과 관리자 Pages 자동 배포 후 실제 화면 로그인은 별도 확인한다.

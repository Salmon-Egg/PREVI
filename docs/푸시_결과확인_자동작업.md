# 푸시 결과 확인 자동 작업

2026-10-29 · BE A · DB/API 형식 변경 없음

기존에는 `NotificationSender.check_receipt()`가 있어도 자동 작업에서 호출하지 않았다. 이제 `daily_check`와 `daily_check --reminders-only`가 시작할 때 미확인 결과를 조회한다. 기존 5분 간격 알림 작업을 운영 컴퓨터에 등록하면 결과 확인도 함께 실행된다.

- Expo에 접수된 `accepted` 상태 중 `sent_at` 기준 15분 이상 지난 알림만 조회한다.
- 한 회차 최대 1000개를 오래된 순서로 읽고, 조회 가능한 티켓은 한 번의 결과 요청으로 묶는다. 대기량이 크면 다음 회차에서 이어 처리한다.
- 성공 결과는 기존 `delivered`, 명시적 오류는 `failed`로 저장한다. `delivered`는 Apple/Google 푸시 서비스로의 인계 성공이며 실제 화면 표시나 사용자의 읽음을 보장하지 않는다.
- 결과가 아직 없으면 `accepted`를 유지해 다음 회차에서 다시 확인한다. 24시간이 지났거나 티켓 ID가 없으면 `unknown`으로 두어 영구 대기를 막는다.
- 통신 실패·깨진 응답은 성공으로 저장하지 않으며 오류 수를 반환한다. 작업 종료 코드에도 오류를 반영한다.
- `DeviceNotRegistered` 오류에서는 전송 당시 토큰과 현재 토큰이 같은 경우에만 지운다. 새 기기로 등록한 토큰은 보존한다.
- 결과 확인 작업은 새 푸시를 보내거나 실패 알림을 재전송하지 않는다. `PUSH_ENABLED=false`에서도 과거에 이미 접수된 티켓의 결과는 확인할 수 있다.

Expo는 결과 확인을 전송 후 약 15분 뒤에 권장하고 결과를 24시간 후 삭제하며 요청당 1000개 티켓을 지원한다. [공식 안내](https://docs.expo.dev/push-notifications/sending-notifications/)

## 운영 반영

기존 자동 작업이 이미 등록돼 있다면 코드 업데이트 후 다음 실행부터 적용된다. 아직 등록하지 않았다면 운영 컴퓨터에 맞는 작업 스케줄러 또는 cron 등록이 필요하다. 이번 코드 작업에서 운영 작업 등록이나 실제 폰 푸시는 실행하지 않았다.

실제 폰 도착 및 알림 클릭 이동 확인은 FE 개발 빌드와 함께 별도로 진행한다.

## FE가 바로 고칠 수 있는 요청 불일치

### 마감 알림 받기 (10)

ChatPanel.tsx는 현재 다음처럼 서버가 지원하지 않는 source를 보냅니다.

```ts
// 현재: TodoInput.source는 notice만 허용하므로 422
await api.post('/todos', { ...a.payload, type: 'deadline', source: { kind: 'chat', id: convId } });
// 기존 API 계약을 유지하는 수정: 채팅에서 만든 수동 할 일로 등록
await api.post('/todos', { ...a.payload, type: 'deadline' });
```

대화 ID를 DB source로 저장하는 기능까지 필요하면 요청·DB 문서를 먼저 고치고 조장 확인을 받아야 합니다.
이 서버 PR에서는 지원하지 않는 source를 조용히 받아들이거나 다른 사용자 대화 ID를 신뢰하지 않습니다.

### 영역별 목록 (13)

`/grades`의 학기별 items를 펼쳐 각 과목에 term을 붙이고 AreaCard에 전달합니다.
주전공 표시는 전공 필수/선택/기초/핵심/심화를 전공으로 묶고 교양 필수/선택 등을 교양으로 묶습니다.
서버 기준은 `server/logic/graduation.py`의 MAJOR_AREAS/GENERAL_AREAS와 같아야 합니다.
F·P와 재수강 중복을 처리하는 학점 합계는 서버 earned 값을 사용하며, 목록이 없다고 성적이 없다고 안내하지 않습니다.
`earned_total`, `remaining_total`, `areas[].earned`, `requirements[].done`은 확인 불가 시 null일 수 있으므로 타입과 화면에서 구분해야 합니다.

### 졸업 정보 오류와 다른 학업 메뉴 (14)

`study/index.tsx`는 졸업 API StateView 안에 성적·시간표 링크까지 넣어 두었습니다.
졸업 기준 확인 실패 안내와 독립적인 성적·시간표 이동 버튼을 분리하면 미지원 학과도 학업 정보를 볼 수 있습니다.
부전공·복수전공은 주전공 최소 기준일 뿐이므로 추가전공 확인 필요 문구를 가리지 말아야 합니다.

## 인증 메일 설정 확인

- Supabase 기본 발송은 조직 멤버 주소로 제한되므로 실제 학생 이메일에는 별도 SMTP 설정이 필요할 수 있습니다.
- 앱이 숫자 인증번호를 받는 흐름이므로 Magic Link 템플릿에 `{{ .Token }}`이 있어야 합니다.
- `supabase/email_templates/magic_link_otp.html`은 적용할 템플릿 초안이며 프로젝트에 자동 적용하지 않았습니다.
- 참고: https://supabase.com/docs/guides/auth/auth-smtp / https://supabase.com/docs/guides/auth/auth-email-passwordless
- 실제 학생 메일을 임의로 생성하거나 시험 메일을 보내지 않았습니다. 공급자 SMTP 설정과 실제 수신 확인은 프로젝트 관리자가 해야 합니다.

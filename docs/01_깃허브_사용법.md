# 깃허브 사용법 (처음 쓰는 사람용)

명령어를 외울 필요가 없도록 **GitHub Desktop**(버튼으로 쓰는 프로그램)을 기준으로 설명합니다.

---

## 1. 먼저 알아 둘 말 7개

| 말 | 쉽게 말하면 | 비유 |
|---|---|---|
| **레포 (repository)** | 우리 프로젝트 파일이 모두 들어 있는 공용 폴더 | 팀 공유 드라이브 |
| **클론 (clone)** | 레포를 내 컴퓨터로 처음 한 번 복사해 오기 | 공유 드라이브를 내 PC에 동기화 |
| **브랜치 (branch)** | 원본을 건드리지 않고 내 작업만 따로 하는 갈래 | 원본 문서의 "사본"에서 작업 |
| **커밋 (commit)** | 지금까지 고친 내용을 메모와 함께 저장하기 | 게임 세이브 |
| **푸시 (push)** | 내 컴퓨터의 커밋을 깃허브에 올리기 | 세이브 파일 업로드 |
| **풀 (pull)** | 깃허브의 최신 내용을 내 컴퓨터로 받기 | 남들이 올린 것 다운로드 |
| **PR (Pull Request)** | "제 작업을 원본(main)에 합쳐 주세요" 하는 요청 | 결재 올리기 |

`main`은 **모두가 함께 쓰는 원본 갈래**입니다. `main`은 항상 "돌아가는 상태"여야 해서, 직접 고치지 않고 PR로만 합칩니다.

## 2. 처음 한 번만 하는 준비

### 2-1. 깃허브 계정과 초대 수락
1. https://github.com 에 가입합니다. (이미 있으면 건너뜀)
2. 조장에게 **내 깃허브 아이디**를 알려 줍니다.
3. 이메일로 온 초대 2개를 **수락**합니다.
   - 레포 초대 (seokyeong-ai-secretary)
   - 작업 보드 초대 (Project)

### 2-2. GitHub Desktop 설치
1. https://desktop.github.com 에서 내려받아 설치합니다.
2. 실행하고 **Sign in to GitHub.com**으로 내 계정에 로그인합니다.
3. 이름·이메일을 묻는 화면이 나오면 그대로 **Finish**를 누릅니다.

### 2-3. 레포를 내 컴퓨터로 가져오기 (클론)
1. GitHub Desktop 위쪽 메뉴 **File → Clone repository**
2. 목록에서 `Salmon-Egg/seokyeong-ai-secretary` 선택
3. **Local path**(내 컴퓨터 어디에 둘지)를 확인하고 **Clone**

이제 내 컴퓨터에 `seokyeong-ai-secretary` 폴더가 생겼습니다. 이 폴더 안에서 작업합니다.

## 3. 매번 작업할 때의 순서 (이것만 기억하세요)

```
카드 고르기 → 최신 받기 → 브랜치 만들기 → 작업 → 커밋 → 푸시 → PR → 확인받고 합치기
```

### ① 작업 보드에서 카드 고르기
1. [작업 보드](https://github.com/users/Salmon-Egg/projects/2/views/1)에서 내 카드를 엽니다.
2. 오른쪽 **Assignees**에 나를 지정하고, 상태를 **In Progress**로 옮깁니다.
3. 카드가 "Draft"(초안)라면 **Convert to issue** → 레포 `seokyeong-ai-secretary` 선택.
   그러면 카드에 **번호(#12 같은)**가 생깁니다. 이 번호를 기억해 두세요.

### ② 최신 내용 받기
GitHub Desktop 위쪽 **Current branch**가 `main`인지 확인하고 → **Fetch origin** → (버튼이 바뀌면) **Pull origin**

> 남이 올린 최신 내용 위에서 시작해야 나중에 부딪히지 않습니다. **작업 시작 전에 꼭!**

### ③ 내 브랜치 만들기
1. **Current branch** 클릭 → **New branch**
2. 이름을 규칙대로 적습니다. ([작업 규칙](02_작업_규칙.md) 참고)
   - 예: `fe/M-1-로그인`, `be/grades-api`
3. **Create branch** → 다음 화면에서 **Publish branch**

### ④ 작업하기
평소처럼 VS Code 등으로 파일을 고칩니다.
GitHub Desktop 왼쪽 **Changes**에 고친 파일이 자동으로 나타납니다.

### ⑤ 커밋 (저장)
1. 왼쪽 아래 **Summary**에 무엇을 했는지 한 줄로 적습니다.
   - 좋은 예: `로그인 화면 만들기`, `성적 저장 API 추가`
   - 나쁜 예: `수정`, `asdf`, `최종_진짜최종`
2. **Commit to 내브랜치이름** 클릭

작업 중간중간 자주 커밋해도 됩니다. (세이브는 자주!)

### ⑥ 푸시 (올리기)
위쪽 **Push origin** 클릭. 이제 내 작업이 깃허브에 올라갔습니다.

### ⑦ PR 만들기 (합쳐 달라고 요청)
1. 푸시하고 나면 나오는 **Create Pull Request** 버튼 클릭 → 브라우저가 열립니다.
2. 제목: 무엇을 했는지 (예: `M-1 로그인 화면`)
3. 본문에 이미 적혀 있는 체크리스트를 채우고, `Closes #카드번호`를 적습니다.
   - 예: `Closes #12` → PR이 합쳐지면 카드가 자동으로 Done이 됩니다.
4. 오른쪽 **Reviewers**에 확인해 줄 팀원 1명 지정 → **Create pull request**

### ⑧ 확인받고 합치기
- 확인하는 사람: PR의 **Files changed** 탭에서 바뀐 내용을 보고 **Review changes → Approve**
- 확인이 끝나면 PR을 만든 사람이 **Merge pull request → Confirm merge**
- 끝나면 GitHub Desktop에서 `main`으로 돌아가 **Pull origin**

## 4. 이럴 땐 이렇게

| 상황 | 해결 |
|---|---|
| `main`에서 바로 고쳐 버렸다 (아직 커밋 전) | 그대로 **New branch**를 만들면 고친 내용이 새 브랜치로 따라옵니다. 이때 **Bring my changes to 새브랜치**를 고르세요 |
| 실수로 커밋했다 (아직 푸시 전) | 왼쪽 **History** 탭 → 그 커밋 오른쪽 클릭 → **Undo commit** |
| 푸시까지 했다 | 걱정하지 말고 고친 뒤 다시 커밋·푸시하면 됩니다. 깃은 기록이 남아서 언제든 되돌릴 수 있어요 |
| **충돌 (conflict)** 났다고 나온다 | 같은 파일의 같은 줄을 두 사람이 고친 것입니다. 혼자 해결하려 하지 말고 **그 파일을 고친 사람과 함께** 보세요. GitHub Desktop이 충돌 파일을 보여 주고, 파일 안의 `<<<<<<<`과 `>>>>>>>` 사이에서 남길 내용을 고른 뒤 그 표시들을 지우고 커밋합니다 |
| `.env` 같은 비밀 키를 올려 버렸다 | **바로 조장에게 알려 주세요.** 파일을 지우는 것만으로는 기록에 남아 있어서, 그 키를 새로 발급받아 바꿔야 합니다 |
| 뭔가 꼬였는데 모르겠다 | 아무것도 지우지 말고 화면을 캡처해서 팀 단톡방에 올려 주세요 |

---

## 5. 하지 말아야 할 것 3가지
1. `main`에 직접 커밋·푸시하지 않기
2. 비밀 키(`.env`)를 올리지 않기
3. 다른 사람의 PR을 확인 없이 합치지 않기

# 작업 규칙

짧게 지키기 쉬운 것만 정했습니다. 어떻게 하는지는 [깃허브 사용법](01_깃허브_사용법.md)을 보세요.

## 1. 카드 하나 = 브랜치 하나 = PR 하나
작업 보드의 카드 하나를 고르면 브랜치 하나를 만들고, 끝나면 PR 하나로 올립니다.
여러 카드를 한 PR에 섞지 않습니다. 그래야 무엇이 바뀌었는지 보기 쉽습니다.

## 2. 브랜치 이름

```
구분/카드내용
```

| 구분 | 언제 | 예 |
|---|---|---|
| `fe/` | 앱 화면 작업 | `fe/M-1-로그인`, `fe/T-1-할일목록` |
| `be/` | 서버·데이터·AI 작업 | `be/grades-api`, `be/notice-crawler` |
| `docs/` | 문서만 고칠 때 | `docs/api-명세-수정` |
| `fix/` | 이미 합쳐진 것의 오류 고치기 | `fix/홈-로딩-오류` |

화면 작업이면 화면 번호(M-1, T-1 등)를 넣어 주세요.

## 3. 커밋 메시지
무엇을 했는지 **한국어 한 줄**로 씁니다.
- `로그인 화면 만들기`
- `성적 저장하면 졸업 학점 다시 계산하기`

## 4. PR
- 본문에 `Closes #카드번호`를 꼭 적습니다. (합쳐지면 카드가 자동으로 Done)
- **팀원 1명이 확인(Approve)한 뒤** 합칩니다.
- 확인 요청을 받으면 **하루 안에** 봐 주세요. 마감이 짧습니다.
- 확인할 때는 "돌아가는지, 내 작업과 부딪히지 않는지"만 보면 충분합니다.

## 5. 폴더 담당
내 폴더만 고칩니다. 다른 폴더를 고쳐야 하면 담당자에게 먼저 말합니다.

| 폴더 | 담당 |
|---|---|
| `docs/` | 조장 (누구나 PR은 올릴 수 있음) |
| `app/` | FE A · FE B |
| `server/` | BE A |
| `server/ai/` | BE B |
| `server/jobs/` | BE A · BE B |
| `supabase/` | BE A |

## 6. 바꾸기 전에 조장 확인이 필요한 것
FE와 BE가 함께 쓰는 "약속"이라, 혼자 바꾸면 상대편 코드가 깨집니다.
- [API 명세](04_API_명세.md) (주소, 요청·응답 모양)
- [데이터 표](05_데이터_표.md)
- 챗봇 답변 형식, 알림 형식

바꿀 때는 `docs/` 문서를 먼저 고치는 PR을 올리고, 확인받은 뒤 코드를 고칩니다.

## 7. 비밀 키
- Supabase 키, 푸시 발송 키 같은 값은 **`.env` 파일에만** 두고 절대 올리지 않습니다. (`.gitignore`가 막아 주지만 조심하세요)
- 새 설정값이 생기면 `.env.example`에 **이름만** 추가합니다.
- 진짜 값은 팀 단톡방 공지 등 따로 전달합니다.

## 8. AI 관련
- AI는 `server/ai/client.py`를 통해서만 부릅니다.
- AI에게 주는 지시문은 `server/ai/prompts/` 폴더의 파일로만 관리합니다.
- AI가 써 준 코드는 **내가 설명할 수 있을 때만** 넣습니다. (설명 못 하면 감점 요소)

## 9. 개인정보
- 학번 전체 대신 입학년도만 받습니다.
- 성적은 학생이 직접 입력하며, 가입할 때 수집 항목과 용도를 보여 주고 동의를 받습니다.
- 계정을 지우면 성적을 포함한 데이터도 함께 지웁니다.
- 실제 학생 정보로 테스트하지 않습니다. 시연은 가상 학생 4명(기획안 페르소나)으로 합니다.

## 10. 일정
- **10/28부터는 새 기능을 넣지 않습니다.** 오류 수정만 합니다.
- 우선순위는 `[필수]` → `[권장]` → `(선택)` → 분실물 순입니다.

# 분실물 정답 제한 실제 DB 검증

확인일: 2026-10-31 (한국 시간). 제출 점검표 15번을 학교 서버 API와 실제 Supabase에서 검증했다. 모의 응답이나 가짜 AI를 사용한 결과가 아니다. 이 기능은 AI를 호출하지 않는다.

## 시험 범위

- 기존 제출용 계정과 게시글을 사용하지 않고, 이메일 확인을 완료한 임시 학생 계정 2개와 사진 없는 임시 게시글 4개를 생성했다.
- 게시글 생성·조회·정답 제출은 고정 학교 API의 `/lost-items`를 통해 실행했다. 시도 횟수는 서버 전용 키로 실제 `lost_item_tries`를 읽어 확인했다.
- 비밀번호·인증 토큰·임시 계정 식별자는 이 문서와 공개 저장소에 기록하지 않는다.

| 검사 | 실제 결과 |
|---|---|
| 다른 학생이 정답 없이 상세 조회 | 보관 장소 미노출, 남은 횟수 3, 시도 기록 생성 안 됨 |
| 작성자 상세 조회 | 보관 장소 확인 가능 |
| 다른 학생의 순차 오답 3회 | HTTP 400, 400, 429. DB `tries=3`, `solved=false` |
| 3회 오답 후 정확한 정답 제출 | HTTP 429. 잠금 유지 |
| 공백·대소문자만 다른 정답 제출 | HTTP 200, 보관 장소 확인 가능 |
| 맞힌 뒤 상세 재조회 | 보관 장소 확인 가능 |

| 새 게시글에 같은 조건으로 8건 동시 제출, 2회차 | HTTP 400 2건·429 6건. DB `tries=3`, `solved=false`. 이후 정답도 429 |

## 정리 확인

- 임시 게시글 4개 삭제 후 대상 게시글 0건, 연결된 시도 기록 0건 재조회 확인.
- 임시 계정 2개 삭제 후 각 계정 조회 HTTP 404 확인.
- 정리 오류 0건. 사진을 업로드하지 않아 Storage 삭제 대상은 없었다.
- 기존 계정·기존 게시글·DB 함수·학교 서버 설정은 변경하지 않았다. 서버 재시작도 하지 않았다.

## 결과의 한계

8건 동시 제출을 두 번 수행한 범위에서 제한이 유지됐다. 모든 네트워크 지연·DB 잠금 순서에 대한 수학적 보장이나 대규모 부하 시험 결과는 아니다. 정답과 오답을 섞은 경합, 서로 다른 학생별 횟수 분리, 모바일 화면 상호작용은 이번 시험 범위에 포함하지 않았다.

2026-11-01 KST, 통합본 `3d5f760` 기준. 사용자 요청에 따라 조회·로그인·화면 탐색·로컬 검사를 수행했다. 학교 서버 설정, 학생 성적·시간표·공지 조건은 이번 점검에서 변경하지 않았다. 브라우저의 점검용 로그인은 종료했다.

## 통과한 범위

- 실제 제출용 학생·관리자 계정 주요 조회와 권한 검사 30건 모두 기대한 상태 코드로 응답. 학생 15건(관리자 접근 거부 포함), 관리자 12건, 비로그인 접근 거부 3건. 각 조회는 5초 이내였다.
- 학생: 내 정보·홈·졸업·성적·시간표·과목 검색·학사일정·공지·장학·할 일·알림·분실물·고객센터·대화 목록.
- 관리자: 홈 요약·공지 집계/목록·발송 목록·계정 목록·고객센터·분실물·과목/일정 자료·졸업 기준·피드백·미응답 목록.
- 실제 학생 웹 로그인 → 홈 → 내 학업 → 시간표 → 편집 → 과목 검색 창. College English 검색 결과 6건 및 수업 시간 표시 확인. 추가·저장 버튼은 누르지 않아 학생 시간표를 보존했다.
- 관리자 웹 로그인 → 홈 요약 정상 표시. 확인한 학생/관리자 탭에서 콘솔 error 메시지 0개.
- `AI_FAKE=1`을 명시한 서버 단위 테스트 438개 통과. 실제 모델 정확도 검증을 대신하지 않는다.
- 최신 app lockfile대로 로컬 의존성을 설치한 뒤 `tsc --noEmit` 통과. 앱 소스·lockfile은 변경하지 않았다.

## 확인된 오류·불일치

### 우선 1: 공지 조건의 의미 오류 — BE B

이미 실제 재시험에서 확인한 38·47·57번이 남아 있다. 과정 이수학점과 직전 학기 학점, C학점과 평점 3.0, 누계 평점과 직전 학기 평점을 혼동한다. 추출 실행이 ready인 것과 판정 정확도 통과는 다르다.

`docs/공지9건_재시험_20261101.md` 참고. 수정 후 해당 공지 재해석 → 원문 대조 → 학생 판정 재계산 순서가 필요하다. 수동 재계산은 보류했지만 다음 자동 예약은 저장된 조건을 사용하므로 별도 차단 상태는 아니다.

### 우선 2: 성적증명서 사진 업로드가 현재 비활성 — FE·BE A

공지 사진 오독 때문에 `VISION_MODEL`과 `NOTICE_OCR_DIR`을 비워 둔 결정은 유지한다. 이때 성적증명서 사진도 `/grades/from-file`에서 `503 IMAGE_READER_UNAVAILABLE`로 거부된다. 텍스트 PDF와 직접 입력을 안내해야 하며, 스캔 PDF는 성적증명서 경로에서 읽지 못한다. 공지 OCR 기능과 성적증명서 파일 읽기를 같은 것으로 간주하면 안 된다.

실제 성적증명서나 새 파일을 운영에 올리는 시험은 하지 않았다. 비활성 동작은 코드로 확인했다.

### 우선 3: 홈의 진행 중인 일정 표시 — FE·BE B

11/1 학생 홈의 학사일정 카드가 `다음 일정 · 오늘 / 2학기 중간 강의평가 / 10/20(화) / 다가오는 학사 일정이에요`로 표시됐다. 이벤트는 10/20~11/2 진행 중이다. 날짜가 바뀐 오류가 아니라 진행 중 일정을 d_day=0으로 계산하고 FE가 이를 시작일이 오늘인 것처럼 표현하는 불일치다.

근거: `server/routes/calendar.py:next_calendar_event`, `app/app/(main)/index.tsx:EventCard`. 진행 중 표시와 시작·종료일 안내를 구분해야 한다.

### 설정 화면 접근성 상태 — FE

마이페이지에서 알림 스위치와 글자 크기 버튼이 접근성 트리에 disabled로 나타났다. `Item`은 onPress 없는 줄을 disabled Pressable로 감싸며, 실제 DOM 부모에 aria-disabled=true/pointer-events=none이 있었다. 글자 크기 자식 버튼 자체는 disabled 속성이 없고 pointer-events=auto였다.

따라서 마우스 클릭이 반드시 막힌다고 단정하지 않는다. 읽기 전용 점검 범위를 지키기 위해 알림 설정·기기 글자 크기를 실제로 바꾸지는 않았다. 부모를 일반 View로 바꾸는 등의 조치 전, 키보드·화면 읽기·실제 클릭을 구분해 확인해야 한다.

### 운영 기록 보관 — BE A·보안 담당

API 파일 분리는 적용됐으나 매일 회전·백업 29개 제한은 정확한 30일 경과 삭제를 보장하지 않는다. 이전 journald 기록도 남는다. `보안.md`에 한계를 기록했으며 학교 공용 설정은 변경하지 않는다.

## 테스트 환경에서만 발견한 차이

- 처음 로컬 검사에서 expo-document-picker·react-native-view-shot이 없어 타입 검사가 실패했지만, lockfile 설치 후 통과했다. 그 결과만으로 운영 웹 패키지 누락 오류라고 보지 않는다.
- 실제 AI 설정과 비전 공백을 읽은 초기 서버 검사에서는 사진 업로드 테스트 2개가 실패했다. AI_FAKE=1을 명시하면 438개가 통과한다. 모의 사진 입력 테스트가 실행 환경의 AI 설정에 의존하는 한계이며, 실제 사진 인식 성공 증거가 아니다.

## 남은 제출·시연 확인

- 최신 APK 빌드·설치·실제 폰 권한 및 클릭 동작은 FE 확인이 필요하다.
- 푸시 토큰 0개였으며 폰 푸시 시연 완료 기록은 없다. 앱 안 알림 시연 범위 결정이 필요하다.
- 과목 1,252개 등록·검색은 완료. 파싱에서 제외한 과목명 119개와 학생 과목 선택·저장·겹침 경고 UI는 별도다.
- 가입 메일·6자리 코드는 사용자 확인 완료로 유지하고 다시 시험을 요구하지 않는다.
- 이번 점검은 조회 위주다. 성적/프로필 저장, 공지 발송/삭제, 문의 제출/답변, 분실물 등록/정답·삭제, 실제 AI 대화의 모든 쓰기 동작이 통과했다고 확대하지 않는다.

## 서비스와 외부 연결

- 사용자 systemd와 `Linger=yes` 설정 확인. `previ-ollama`, `previ-api`, `previ-web`, `previ-share`가 active인 출력 확인 후, ngrok 연결·`previ-ngrok` active도 사용자 확인.
- 수집·일일 점검·reminders 타이머 등록. reminders의 10/30 03:00 실행은 오류 0건으로 종료. 수집과 아침 점검의 실제 실행 성공은 미검증.
- 고정 API: `https://amused-swirl-reprocess.ngrok-free.dev`. 외부 `/health`에서 status=ok 확인. 무료 ngrok API 클라이언트에는 안내 페이지 대신 JSON을 받도록 헤더를 추가했다.
- 학생 웹은 공유 스크립트에서 고정 API를 적용해 재빌드한다. 사용자에게 새 웹에서 실제 로그인·AI 답변 수신을 확인받았다. 웹 공유 주소는 임시이며, 현재 주소는 서버의 `~/.local/state/previ-share/addresses.txt`에서 확인한다.
- 공유 스크립트는 HTTP/2를 사용하고 서버 내부 상태를 확인한다. 서버에서 임시 공개 주소를 조회하지 못했다는 이유만으로 터널을 반복 종료하지 않도록 수정했다.
- 서버 재부팅·완전 로그아웃 이후 자동 복구와 동시 사용자 부하 검사는 미검증.

## Supabase·관리자·분실물

- 012번: 실제 DB에서 `messages.feedback`와 `unanswered_questions.status/cause/resolved_at` 조회 성공. 인덱스·전체 권한과 SQL 실행 이력까지 확인한 것은 아니며 파일을 중복 실행하지 않는다.
- 서버 `ADMIN_EMAILS` 미설정(0개)을 확인한 뒤 사용자가 학교 이메일을 입력해 저장했고 API를 재시작했다. 새 설정으로 관리자 로그인하는 최종 검증은 별도 확인 필요.
- 관리자 공지 저장과 학생별 판정 확인. 전체 대상 `테스트2`는 등록 03:04 / 마감 03:03으로 기본 목록에서 숨겨졌으며, 학생의 마감 지난 공지 보기에서 조회되는 것을 사용자 확인.
- 013번: 사용자가 SQL을 오류 없이 실행했다고 보고. 이후 `lost_items`, `lost_item_tries`의 필요한 열과 `lost-items` 버킷 존재를 실제 조회로 확인. 버킷은 public=true, 5,242,880바이트, image/jpeg·image/png·image/webp이다.
- SQL 권한 조회 결과: authenticated의 answer 조회=false, storage_place 조회=false, title 조회=true, lost_item_place(bigint,text) 실행=true (사용자 결과 확인).
- 실제 학생 로그인으로 받은 토큰을 사용한 REST 검사 결과도 answer=403, storage_place=403, title=200으로 사용자 확인. 토큰·조회된 정답은 출력하거나 보관하지 않았다.
- 학생 UI에서 사진 포함 게시글 등록·삭제를 사용자 확인. 삭제 후 읽기 전용 전수 대조 시 남은 게시글 2개, 참조된 사진 2개, Storage 사진 2개였으며 참조 없는 사진과 누락된 참조 사진은 각각 0개였다. 삭제 전 개별 사진 경로를 기록한 전후 비교 검증은 아니다.
- lost_item_place의 다른 학생 정답 입력·3회 제한·동시 시도 처리는 실제 Supabase에서 별도로 검증하지 않았다.

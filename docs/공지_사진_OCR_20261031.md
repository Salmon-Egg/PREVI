# 공지 사진 CPU OCR 보완

## 실측 결과

- Gemma3 4B·12B 모두 한글 포스터 금액·문구에 오독이 있었다. 12B도 정확도 통과로 간주하지 않는다.
- Tesseract kor+eng 방식 3: 공지 54 장학금 800만 원, 상금 200만 원, 선발 대상은 개선됐지만 모집 날짜가 깨짐.
- 공지 48 방식 3은 지원 비율 표를 누락했다. 표 영역 확대·방식 6에서는 둘째 70% 등 비율을 복구했지만 첫 행과 일부 문구는 여전히 오독했다.
- 따라서 임의의 사진을 자동 판정에 쓸 정확도가 검증된 상태는 아니다.

## 변경

- `NOTICE_OCR_DIR`을 설정하면 공지 사진은 그 환경의 Tesseract를 CPU 2스레드, 시간 제한 60초, kor+eng, 방식 6으로 읽는다. 비우면 기존 비전 모델 사용.
- 사진별 수동 좌표는 코드에 넣지 않았다. 전체 사진 방식 6의 실제 출력은 서버에서 별도 확인해야 한다.
- 첫 사진이 300자 이상이라는 이유로 두 번째 사진의 지원 조건 표를 생략하던 문제를 수정했다. 충분한 PDF/HWP가 있으면 사진을 건너뛰는 동작은 유지한다.
- 사진 판독과 실패에는 원문 확인 표시를 남긴다. 이 표시가 있는 공지는 학생 판정에서 신청 가능·불가를 확정하지 않고 확인 필요로 처리한다.
- 관리자 승인 기능을 새로 구현한 것은 아니다. 본문의 원문 확인 표시를 해제하는 자동 절차도 없다.
- 성적증명서 사진 기능은 기존 비전 경로를 유지한다.

## 서버 적용 순서

1. 통합본 pull 후 `.venv/bin/python -m pip install -r server/requirements.txt`.
2. 설치된 `/home/namkh69/.local/previ-ocr`의 Tesseract와 tessdata/kor·eng 파일을 확인.
3. `.env`를 바꾸기 전에 `NOTICE_OCR_DIR`을 시험 프로세스에만 지정해 공지 54·48 실제 출력 확인. DB를 수정하지 않는다.
4. 출력 확인 후 같은 값을 서버 `.env`에 저장하고 API 재시작. API와 별도로 실행되는 다음 자동 작업도 해당 값을 읽는다.
5. 기존 35건 재처리 예약의 상태를 확인한다. 이미 `[첨부 내용]`이 저장된 공지는 기존 재등록 스크립트가 다시 선택하지 않으므로 중복 실행만으로 새 OCR 결과로 교체되지 않는다.

테스트: 서버 단위 테스트 385개 통과. 실제 서버의 전체 사진 방식 6·자동 작업은 미검증.

`npm audit` (운영 의존성):

- `admin`: 0건.
- `app`: high 4건, low 5건. `expo` → `@expo/cli`(zod, node-forge), `@expo/config`(deepmerge) 경로입니다. 개발 도구 쪽 경로로 판단했으나 앱 번들 포함 여부를 하나씩 확인하지는 않았습니다.
- `npm audit fix`는 lockfile을 700줄 넘게 바꿔 제출 전 위험이 커서 되돌렸습니다. `--force`는 Expo 51로 내리므로 쓰면 안 됩니다. 제출 후 `npx expo install expo@~58 --fix`로 올리고 다시 확인합니다.
- `server` 파이썬 패키지는 `pip-audit`이 없어 점검하지 못했습니다.

## BE A에게 전달

1. 서버 재배포: 탈퇴 시 사진 삭제 코드(`server/routes/lost_items.py`, `me.py`, `admin.py`)는 재배포해야 적용됩니다. DB 변경은 없습니다.
2. 학교 서버 `.env`에서 `DEV_AUTH`가 꺼져 있는지 확인: 로컬 값은 `1`이고, 학교 서버 값은 확인하지 못했습니다. 켜져 있으면 실제 운영에 쓰면 안 됩니다.
3. 예전에 탈퇴한 계정의 사진: 코드 수정 전에 탈퇴한 계정의 사진은 `lost-items` 저장소에 남아 있을 수 있습니다. 어떤 글에도 연결되지 않은 파일을 찾아 지워 주세요.
4. 이미 가입한 계정의 학번 지우기 (적용 전 확인):

```sql
update auth.users set raw_user_meta_data = raw_user_meta_data - 'student_id' where raw_user_meta_data ? 'student_id';
```

## 확인하지 못한 것

- 실제 휴대폰에서의 화면 읽기(TalkBack, VoiceOver).
- 실제 Supabase 환경의 가입 메일과 사진 삭제. 서버 코드는 모의 응답 테스트로만 확인했습니다.
- 앱 웹판 키보드는 로그인·가입과 약관 창만 직접 눌러 봤습니다. 처음 설정·홈·할 일·학업·장학·행정·마이페이지는 버튼 역할과 이름 구조만 검사했고, 시간표 편집과 분실물은 검사하지 않았습니다.
- 관리자 웹은 로그인 없이 창(Esc, Tab, 포커스 복귀)만 실제로 확인했습니다. 졸업 기준 표의 '자세히' 버튼은 빌드만 확인했습니다.
- 배포된 웹에서의 쿠키. ngrok 무료 주소와 호스팅 서비스가 자체 쿠키를 붙이는지는 확인하지 못했습니다.
